Figma2Beefree

Product Designer · Personal project · April–May 2026

TL;DR

Designers mock up email templates in Figma, but there's no bridge from that canvas into Beefree — every layout gets rebuilt by hand, and small details drift in the handoff. I built a Figma plugin that lets you compose an email visually on the canvas — rows, columns, headings, buttons, images, dividers — using Figma's own native controls, then export it straight into Beefree's schema. A one-click flow takes it further: convert, enrich, log in, and import the finished template directly into RGE Studio, Beefree's studio product, without ever leaving Figma. A companion Claude Code skill closes the other gap — it takes any existing Figma frame, not just ones built with the plugin, and restructures it into something the plugin can export.

The problem

Beefree's email builder and Figma's canvas don't speak the same language. A designer can mock up a perfectly pixel-accurate template in Figma, but turning it into something Beefree can actually render means a developer manually re-creating every row, column, and module, translating fonts, paddings, and colors by hand. It's slow, and every manual step is a chance for the final template to drift from the design.

What I built

A Figma plugin with a module palette — Row, Heading, Paragraph, Button, Image, Divider, List, Menu, Icons — that inserts real Figma nodes onto the canvas, laid out on a 12-column grid so column widths never need manual resizing. Every node carries its Beefree-relevant properties (font, radius, padding, alignment) as plugin data, so editing mostly stays inside Figma's native property panel instead of a custom UI bolted on top — the exception is image URLs, alt text, and links, which get their own fields in the plugin panel since Figma has no native concept of them. Selecting a template frame and exporting produces a valid Beefree Simple Schema JSON — structured rows and weighted columns that map 1:1 to what's on the canvas.

Under the hood

The plugin splits along Figma's own sandbox/UI boundary: code.ts runs inside the Figma sandbox and does all the document work — reading nodes, writing plugin data, the one-click fetch to the Cloudflare Worker — while ui.ts renders the panel and only talks to the sandbox through typed postMessage calls. Four small modules carry the schema logic: exporter.ts turns the Figma tree into Simple Schema, optimizer.ts re-enriches a Full Schema with the Figma-only properties Beefree's conversion API drops, figmaSerializer.ts dumps the raw node tree for debugging exports, and schema.ts holds the Simple Schema types everything validates against.

Closing the last gap

Simple Schema isn't what Beefree's own editor opens — it needs a more enriched "Full" JSON, so a raw export still wasn't an importable template. I added an Optimize tab that re-enriches exported JSON with the Figma-only properties Beefree's own conversion step drops, and a One-click tab that chains the whole thing together: convert, enrich, log in, and import into RGE Studio in a single click. Since Beefree's conversion API won't accept requests from a Figma plugin's sandboxed iframe (it sends Origin: null, and the response has no CORS headers), I stood up a small Cloudflare Worker to proxy the request and pass through the credentials the user enters — session-only, nothing stored. For now the whole flow only works against RGE Studio's PRE (pre-production) environment.

From any Figma frame, not just ones built with it

Building templates from scratch inside the plugin's own row/column palette works well when you're starting fresh — but plenty of templates worth importing already exist in Figma as ordinary mockups, assembled long before the plugin existed. So I paired the plugin with a Claude Code skill that takes any existing Figma frame — however it was built — and rebuilds it into the strict Template → Row → Content Area → Column → module structure the plugin's exporter expects, tagging every node with the plugin data it needs along the way. Point the skill at a frame and it hands back a new, tagged frame sitting right next to the original, ready to select and export. The plugin is no longer limited to templates you build inside it.

Where it stands

It's an unpublished, dev-mode plugin for now — anyone who wants to run it clones the repo and imports the manifest locally — but end to end it works: build a layout on the canvas, and one click later it's a live template in RGE Studio, restricted for now to PRE accounts. What started as a solo build has since gotten sign-off from Beefree's product team to keep pushing it toward a supported internal tool.

What's next

  • Harden the authorization step beyond session-only email/password
  • Align the plugin's UI to RGE Studio's own design language
  • Grow the catalog of prebuilt rows
  • Tighten the TypeScript exporter for closer 1:1 JSON fidelity
